  8. Escalade — utilisez Y, 1, true ou oui. Si Y, renseignez un escalation_reason et un council_theme (sinon l'Engagement #5 le signalera).

📘 Guide complet — Comment remplir votre fichier d'import

Ce guide explique le mécanisme de liaison entre les 3 onglets du modèle Excel, les pièges fréquents, et la façon de gérer les codes manquants. À lire avant de remplir votre premier fichier.

1 · Le principe : une clé partagée entre les 3 onglets

Le fichier comporte 3 onglets de données : Meetings (les PV), Issues (les problèmes soulevés en réunion), Actions (les engagements pris). Les Issues et les Actions doivent être rattachées à leur PV parent via une clé de liaison.

┌─ Onglet Meetings ───────────────────────────────────────┐ │ reference │ site │ dept │ date │ ├────────────────────────────┼──────┼─────────┼──────────┤ │ HGO_Mining_PV_2026-05 │ HGO │ mining │ 2026-05- │ ← Le PV │ HGO_Maintenance_PV_2026-05 │ HGO │ maint │ 2026-05- │ ← Un autre PV │ MGO_Mining_PV_2026-05 │ MGO │ mining │ 2026-05- │ ← Un 3e PV └────────────────────────────┴──────┴─────────┴──────────┘ ↓ │ La référence est la clé ↓ ┌─ Onglet Issues ──────────────────────────────────────────┐ │ meeting_reference │ ord │ title │ cat │ ├────────────────────────────┼─────┼────────────────┼──────┤ │ HGO_Mining_PV_2026-05 │ 1 │ Crusher PLC │ OT │ │ HGO_Mining_PV_2026-05 │ 2 │ WiFi vestiaire │ CN │ │ HGO_Maintenance_PV_2026-05 │ 1 │ GMAO laggy │ AP │ │ MGO_Mining_PV_2026-05 │ 1 │ Tablettes │ HW │ └────────────────────────────┴─────┴────────────────┴──────┘ ↓ ┌─ Onglet Actions ─────────────────────────────────────────┐ │ meeting_reference │ ord │ desc │ link │ ├────────────────────────────┼─────┼────────────────┼──────┤ │ HGO_Mining_PV_2026-05 │ 1 │ Appeler vendor │ 1 │ ← lie l'issue #2 │ HGO_Mining_PV_2026-05 │ 2 │ Test AP supp. │ 2 │ du MÊME PV │ HGO_Maintenance_PV_2026-05 │ 1 │ Migration GMAO │ 1 │ │ MGO_Mining_PV_2026-05 │ 1 │ Acheter charg. │ 1 │ └────────────────────────────┴─────┴────────────────┴──────┘

Deux clés à comprendre :

  • meeting_reference (dans Issues et Actions) doit valoir EXACTEMENT la même chose que reference du PV (copier-coller, sensible à la casse, espaces compris).
  • linked_issue_ord (dans Actions) est le numéro 1-based de l'issue dans la même réunion — pas le numéro global du fichier.
⚠ RÈGLE D'OR — Remplissez la colonne reference à la main dans l'onglet Meetings, puis copiez-la dans meeting_reference des onglets Issues ET Actions. Si vous laissez reference vide dans Meetings, le serveur la générera automatiquement, mais vous devrez deviner exactement la chaîne fabriquée pour la coller dans Issues/Actions — source d'erreurs.

2 · Format canonique de la référence

Format recommandé : CODESITE_Departement_PV_AAAA-MM.

ExempleDécodage
HGO_Mining_PV_2026-05PV Mining de mai 2026 à Houndé
MGO_Maintenance_PV_2026-05PV Maintenance de mai 2026 à Mana
IGO_Geology_PV_2026-04PV Geology d'avril 2026 à Ity

3 · Astuce Excel : générer toutes les références d'un coup

Pour gagner du temps avec beaucoup de PV, mettez cette formule dans la cellule reference (A2) de l'onglet Meetings :

=B2 & "_" & MAJUSCULE(GAUCHE(C2;1)) & STXT(C2;2;100) & "_PV_" & TEXTE(D2;"AAAA-MM")

(Adaptez B2 = site_code, C2 = department, D2 = meeting_date selon l'ordre de vos colonnes.) Étirez la formule sur toute la colonne, puis faites Copier → Collage spécial → Valeurs uniquement pour figer les références en texte. Vous pourrez alors copier-coller ces valeurs dans meeting_reference des onglets Issues et Actions.

4 · Piège : deux PV du même département dans le même mois

La règle implicite est « un PV par mois par département par site ». Si vous avez tenu deux réunions Mining à Houndé en mai 2026, le serveur rejettera le doublon :

❌ Ne pas faire :

reference │ date HGO_Mining_PV_2026-05 │ 2026-05-03 HGO_Mining_PV_2026-05 │ 2026-05-24 ← REJETÉ (doublon)

✅ À faire — ajoutez un suffixe manuel :

reference │ date HGO_Mining_PV_2026-05-03 │ 2026-05-03 HGO_Mining_PV_2026-05-24 │ 2026-05-24

… puis copiez-collez ces références dans meeting_reference des Issues/Actions correspondantes.

5 · Codes manquants (intake_source, department, category…)

L'import est strict : si un code utilisé dans votre fichier n'existe pas dans la base, la ligne sera rejetée avec le message Unknown <champ> "<code>". Allowed: …. Trois solutions :

  • Si vous êtes super_admin — la prévisualisation affichera un bouton « + Créer ce code » à côté de chaque erreur. Cliquez, remplissez le nom EN/FR, validez, et la prévisualisation se relance automatiquement. Le code est créé immédiatement.
  • Sinon — contactez votre super_admin pour qu'il ajoute le code via Reports → Admin → Meetings — Codes de référence, puis relancez votre import.
  • Solution de contournement — utilisez un code existant proche (consultez l'onglet Codes du modèle pour la liste à jour) en attendant la création du nouveau code.

6 · Lookup vs texte libre — qu'est-ce qui est configurable ?

Toutes les colonnes du fichier ne fonctionnent pas pareil. Il y a deux familles :

  • Colonnes à code (lookup) — il faut utiliser une valeur d'une liste prédéfinie. Si la valeur n'est pas dans la liste, l'import refuse la ligne. Ces listes sont gérables par le super_admin via Reports → Admin → 🗂 Meetings — Codes de référence.
  • Colonnes texte libre — tu écris ce que tu veux directement dans la cellule. Pas de liste à respecter. Ce sont les contenus de la réunion : noms, descriptions, notes, dates, priorités, etc.
⚠ Piège fréquent — priority_1, priority_2, priority_3 ne sont PAS des codes. Ce sont les 3 priorités décidées en réunion, à écrire en texte libre dans les cellules. Exemple :

priority_1 = « Réparer le PLC du concasseur — downtime 30 min/semaine »
priority_2 = « Couverture WiFi vestiaire — ajouter 2 AP »
priority_3 = « Inventaire des tablettes de production avant T3 »

Les valeurs « Top priority 1 / Top priority 2 » du modèle sont des exemples à remplacer.

7 · Recette pratique — 5 PV, 30 issues, 15 actions

  1. Onglet Meetings d'abord — remplissez 5 lignes avec une reference unique sur chacune.
  2. Copiez chaque référence dans le presse-papier une par une, puis remplissez les issues du PV correspondant en collant la référence dans meeting_reference autant de fois que ce PV a d'issues. Numérotez ord de 1 à N pour les issues du même PV.
  3. Onglet Actions — même logique. Pour chaque action, collez la même référence que son PV parent. Si l'action est liée à une issue précise du même PV, mettez le numéro ord de cette issue dans linked_issue_ord.
  4. Lancez la prévisualisation — vérifiez : ✓ 5 meetings, 30 issues, 15 actions, 0 erreurs. Si erreurs → corriger et relancer.
  5. Validez l'import une fois la prévisualisation propre. Les références déjà existantes seront mises à jour en place.

9 · FAQ

Q : Puis-je importer plusieurs sites dans le même fichier ?
Oui — tant que chaque PV a sa propre reference unique.

Q : Que devient mon fichier après l'import ?
Rien — le contenu est écrit dans la base de données, le .xlsx lui-même n'est pas conservé.

Q : Et si je me trompe et que je veux corriger ?
Re-uploadez le même fichier avec la même reference et les valeurs corrigées. Le serveur met à jour le PV en place (pas de doublon).

Q : Je n'ai pas tous les détails d'un PV. Puis-je le saisir partiellement ?
Oui. Les colonnes optionnelles (priority_1/2/3, next_meeting_date, etc.) peuvent rester vides. Seuls site_code, department et meeting_date sont obligatoires sur l'onglet Meetings.

Q : Y a-t-il une limite de taille ?
30 Mo par fichier. Cela couvre largement plusieurs mois de PV historiques.
