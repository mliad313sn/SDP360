📡 Infra WAN / Availability — Meraki & OpManager

Feeds the WAN Health dashboard and the report's infra auto-fill. Meraki supplies per-uplink WAN availability/quality — WAN is the one thing OpManager can't see (MX firewalls have no SNMP interfaces). LAN / WLAN / Servers flow the usual way: OpManager → Analytics Plus → OPS (OPS reads the prepared view, it never polls OpManager directly). The module is inert until configured; the Meraki numbers are only trustworthy after the one-time calibration node tools/meraki/calibrate.js (locks the missing-interval policy against Meraki's own "% Time Up").

Meraki (WAN)

Origin + /api/v1. Leave as the default unless you use a regional shard.
The numeric id from Organization → Settings, or from GET /organizations with your API key. NOT the /o/<slug> in the dashboard URL — that's a different id.
Set to whichever value calibrate.js reconciles against Meraki's own "% Time Up".
100 = règle « loss<100 » (défaut, trop tolérant). Baisse (~15-25) pour approcher le « % Time Up » de Meraki, qui compte les fortes pertes comme down. Puis Sync WAN now et recharge WAN Health.
Optionnel — compte un intervalle très lent comme down (les timeouts que Meraki voit, ex. > 1000).

Qualité voix — modèle E (ITU-T G.107) → MOS

La Qualité (onglet WAN Health) est l'indice R (0-100) du modèle E converti en MOS (1 à 5). Défauts G.711 filaire. Après tout changement : Sync WAN now puis recharge WAN Health.

G.711 = téléphonie « pleine bande » (cas normal en entreprise). G.729 = codec compressé, plus sensible à la perte.
0 = filaire (défaut). Un lien satellite/VSAT tolère plus de latence → mettre 10-20 remonte le MOS. S'applique à tous les liens (pas encore par site).

🔔 Alertes SLA dans Teams Prévenir chaque groupe, dans son canal Teams, avant le dépassement du SLA

Toutes les 5 min, le dashboard lit les tickets ouverts dans l'API de ServiceDesk Plus Cloud et poste une carte par groupe dans le canal Teams du groupe : 1re réponse bientôt due / dépassée, résolution bientôt due / dépassée, ticket non assigné. Une seule alerte par ticket et par type. Désarmé par défaut. Les secrets et les URL de webhook ne sont jamais réaffichés : laissez un champ vide pour conserver la valeur enregistrée.

1 · Accès API ServiceDesk Plus Cloud

Client OAuth Zoho (« Self Client ») avec le scope SDPOnDemand.requests.READ.

2 · Canaux Teams par groupe

Nom exact du groupe SDP → URL du webhook Workflows du canal (« Publier dans un canal lorsqu'une requête webhook est reçue »). Groupe * = canal par défaut pour les groupes non listés.

3 · Règles

Les tickets créés avant sont ignorés (0 = sans limite) — et la lecture de l'API s'arrête là.
JSON. fr_soon_minutes = minutes avant l'échéance de 1re réponse, par priorité ; res_soon_pct = % du délai de résolution consommé ; breach_window_minutes = un dépassement plus ancien n'est pas annoncé ; kinds = activer / couper chaque alerte.
