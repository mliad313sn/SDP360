# ADR W2-ENGINE — calendars, resource pool, levelling, baseline slots and MSPDI on the W1 engine

- **Status:** accepted for the sandbox (engineering choices). Every behaviour is behind a PROPOSED switch, default off.
  No business policy is decided here: who maintains the pool, the rates, and when to arm the switches are PMO / Finance
  decisions.
- **Context:** PPM parity wave W2 (`docs/audits/2026-11-12-ppm-parity/README.md` §5). W1 delivered a pure date-based
  CPM (`services/ppm/scheduleEngine.js`) with typed links and working-day lags, the 8 constraints and deadlines.

## Decisions

1. **Lag units inside the existing JSON link list** (`dependency_links[].lag_unit` = `d` | `ed` | `%`), not a new link
   table: the W1 store, the CR simulation and the Gantt already read that list; an absent unit is today's behaviour.
   Elapsed lag counts calendar days from the predecessor's boundary and lands on the successor's calendar; % lag is a
   share of the predecessor's duration rounded to whole working days (MS-Project keeps fractions of a day; our engine
   is day-grained — documented).
2. **Side tables, not new `portfolio_tasks` columns** (migration 105): `ppm_task_engine` (calendar, priority, levelling
   delay), `ppm_project_engine`, the pool tables. `portfolio_tasks` is read with `SELECT *` by many readers; rates and
   costs must never ride along to non-money readers (same reason as W1-EVM's `ppm_task_evm`).
3. **Calendars build on `site_calendar`** (migration 037) through `use_site_holidays`, with a base-calendar chain and
   day-range exceptions that override both the work week and holidays. Effective calendar of a task = task > primary
   work resource > project > Mon–Fri. MS-Project schedules each assignment on its own resource calendar; using the
   primary resource's calendar for the whole task is a deliberate simplification.
4. **Contours spread work over the scheduled duration** in whole minutes (largest remainder), so time-phased hours add
   up exactly; the 8 shapes are MS-Project-like, not certified copies of MS-Project's tables, and MS-Project would
   lengthen a fixed-units task instead.
5. **Levelling = serial schedule iterated with the CPM**, delay-only, expressed as MS-Project's *levelling delay* (working
   days added after all network requirements). Order of service fixed for the whole run (priority → unlevelled start →
   total float → id) and topological (never before a task's own predecessors): an order recomputed from the current
   dates made tasks chase each other and never converge (measured). Inside a pass a successor starts its search where
   its delayed predecessor pushes it; the next CPM run corrects any approximation. Capped at 20 passes; `converged`
   says honestly whether the last pass still moved something. Within the project only. It NEVER writes: the route
   returns a proposal and a fingerprint of the plan; apply re-computes the proposal and refuses a stale fingerprint.
6. **Baseline slots in their own append-only table** (`ppm_baseline_slots`), not in `portfolio_baselines`: W1-EVM and
   the A-27 history read the latest `portfolio_baselines` version as THE approved baseline — a comparison snapshot
   must never become it. Same payload family as A-27 plus work and cost. Immutable once saved (MS-Project overwrites a
   slot; here a slot is history — documented difference).
7. **MSPDI with a small in-repo XML reader/writer** (no new dependency): the tolerant reader refuses any DTD (no entity
   expansion, no external entity), decodes the five XML entities and numeric references, ignores namespaces. The
   round-trip contract is `normalizeModel(fromXml(toXml(m))) == normalizeModel(m)` and `toXml` is a fixed point; the
   1,000-task golden file is regenerated by `tools/ppm/gen-mspdi-golden.js` (seeded) and pinned by SHA-256 instead of
   committing a 1.2 MB fixture. Import goes into an EMPTY project only (dry run by default, apply = committee).
8. **Schedule API under `ppm_schedule_engine_v2_ui`** (the existing W1 switch for scheduling surfaces) so W2-ui can
   read one contract; the extra blocks appear only when their own switch is on.

## Consequences

- Nothing changes for any user until a switch is turned on. Rolling back = switches to `'0'`; the schema rollback is
  `db/postgres_rollback/105_ppm_engine_w2_drop.sql` (proved by `tests/ppm-rollback-scripts.test.js`).
- Human checks left: open an exported file in MS Project (licence), confirm the % lag encoding, Finance to own rates.
