# ADR-PORTFOLIO-LOT1 — Project register identity and intake fields

- **Status:** accepted for engineering (AI decision, reversible, sandbox). The business values it seeds are **PROPOSED** —
  nothing here is a PMO approval.
- **Date:** 2026-11-20 · **Author:** Claude (AI) · **Review:** AI self-review only — not an independent review.
- **Context:** `docs/sdp360/portfolio-spec/IT-PORTFOLIO-RECONSTRUCTION-SPEC.md` §5–§19, §31 and the gap analysis
  `docs/sdp360/portfolio-spec/PORTFOLIO-SPEC-GAP.md` (Lot 1). Evidence: `docs/agent-execution/PORTFOLIO-LOT1.md`.
- **Switch:** `ppm_intake_register_enabled` (report_config, default `'0'` = today). Migration
  `db/postgres/reports/117_ppm_intake_register.sql` (rollback `db/postgres_rollback/117_ppm_intake_register_drop.sql`).

## Decisions

1. **Project id `PRJ-{YEAR}-{SEQ}`** is a new column `project_ref`, generated by the store at creation (the three
   creation paths: portfolio PUT, RFI conversion, template), from a per-year counter `ppm_project_ref_seq` incremented by
   `INSERT … ON CONFLICT DO UPDATE … RETURNING` (row lock → two concurrent creations never share a number; nothing ever
   decrements → a deleted or purged project never frees its number; gaps are allowed). Unique partial index; a trigger
   refuses changing or clearing a set id, even in SQL. YEAR = creation year. The user-typed `key` stays (existing projects
   keep it, it stays editable). Existing projects get an id only through `tools/ppm/backfill-project-ids.js`
   (`--dry-run` default; ordered by created_at, id; soft-deleted included; same counter as live creation).
   Rejected: `nextRef` max+1 (reuses a number after a purge), using the IDENTITY id (not year-scoped), replacing `key`.
2. **Ownership fields reuse the existing columns:** business sponsor = `sponsor`, IT owner = `owner` (both keep their
   freeze rules: owner after proposal, sponsor after approval); only `delivery_lead` is new. The API accepts the spec
   names `business_sponsor` / `it_owner` as aliases. Rejected: three new columns duplicating fields that the stage gates
   and the separation-of-duties rules already read.
3. **Value states** (spec §31.10): a JSON map `value_states {field: tbc | na | none_known}` next to the values. Blank =
   NULL and no state (unknown, "—"); zero = a measured value; a state is stored only while the field is NULL (a value
   sent clears its state; a state sent for a field holding a value → 400 `VALUE_STATE_CONFLICT`); `none_known` only for
   the project-level `dependencies` / `risks` declarations (and only that state for them). Lists that already carry a
   TBC code (budget status, decision required) use the code, not the state.
4. **Zero budget** stays a measured value (null-vs-zero doctrine). The spec's "budget missing or zero = error" (§20)
   becomes a **warning** `BUDGET_ZERO` on write when the status is not `not_budgeted` — PROPOSED; the data-quality engine
   (Lot 2) decides how it scores. Roles held by one person → warnings `ROLES_SAME_PERSON` / `ROLES_OVERLAP`, never a
   refusal (PROPOSED).
5. **Reference lists** live in one table `ppm_lookup_values (domain, code, labels EN/FR, colour token, order, default,
   proposed, active)`. A value is never deleted — retired (`active = 0`) and kept on the projects that carry it; a list
   value is validated only when it CHANGES, so an unchanged retired value never blocks an edit. Locked domains
   (`project_status`, `decision_required`, `schedule_confidence`) mirror codes the logic reads: relabel / recolour /
   reorder only. Colour = a brand token name (no raw colour). Seed: spec values; priority meanings, risk levels and effort
   bands are `proposed = 1`; **no default is seeded** (a default would pre-fill a business value). Admin = admin tier
   (`requireAdminTier`, hierarchical); the catalogue read is any session. Site restriction of a value (spec §19) is not
   built — no consumer needs it in Lot 1.
6. **Who writes projects is unchanged:** committee + admin tier via the existing `PUT /api/governance/portfolio/project`.
   Contributor creation (spec §27) widens write access and stays an owner decision.
7. **Switch off = today:** the store hides every intake column from the project rows it returns (portfolio, project
   detail, stage move), ignores intake fields on writes and generates no id; the intake routes answer 404; the page has no
   Intake tab. The store reads the switch through an injected `intakeOn()` (other store callers default to off).
8. **Money rule:** budget status, approval date and reference are stripped for readers who may not see amounts, like
   `budget` / `spent` (conservative choice). No base-currency conversion: `fx_rates` are not certified, so a converted
   amount would be invented — it stays unknown (spec §11 base amount → later lot, needs Finance-certified rates).
9. **Field guidance** is data (`services/ppm/intakeFields.js GUIDE`, EN + FR: description, why, good example, common
   mistake, level). `required` levels are PROPOSED (Lot 2 decides any enforcement).

## Consequences

- Reversible: switch to `'0'`; the manual rollback removes the columns, ids and lists (ids are meant to be permanent —
  take a dump first).
- Human decisions unblocked / still needed: PMO review of the PROPOSED reference data before arming; whether to run the
  id backfill (permanent); whether contributors may create projects (separate access-policy decision).
