How the pieces connect

FK-linked internally

Each module is a small tree: md_meetings→md_issues→md_actions, insp_inspections→findings/actions/photos/signatures, tracker_years→pillars→activities→inputs_v2, weeks→weekly_reports→infra_kpis/lights/action_items.

Soft-linked by code (no FK)

Helpdesk hot data (request_records, change_records, survey_*) and assets carry free-text site/group columns matched in application code — never a DB FK. Lookup tables (PK on code) are referenced by value.

Backup & rollback

One pg_dump of sdp_dashboard is the whole backup unit (_sdp_admin option 5). Per-module rollback = unset its *_BACKEND flag + restart; the frozen SQLite .db files are kept as archives.

Cohabitation

sdp_dashboard is a peer of fmp_v2 (the 4MyPeople appliance) on the same cluster. 4MyPeople's destructive ops are scoped to fmp_* — never the SDP database.
