# PMO UX — project / portfolio pages (2026-11)

> Engineering work by an AI agent on branch `feat/pmo-ux`. Layout, ergonomics and wording only: no new business
> feature, no formula, permission or data change. Nobody accepted, approved or signed anything; the source review
> (`ux-committee/pmo.md`, 22 findings) is an AI committee review, not user research.

**Scope owned here:** `public/project.html`, `public/portfolio*.html`, `public/lib/ppm*.js|css`, `public/lib/gantt*.js|css`,
`public/lib/portfolio*.js`. The shell, tokens, `brand/components.css`, `cockpit.html` and `rfi.html` belong to another
work stream (see the "not ours" lines below).

**Building blocks**
- `public/lib/ppmUx.js` + `ppmUx.css` — page frame (`.ppm-page`, `.ppm-page-header`), drawer, toast, inline form
  message, stage stepper, progress bar, chip multi-select, gate checklist builder, sortable table, segmented sub-tabs,
  date / number through `lib/format.js` (SDPFormat).
- `public/lib/ppmLabels.js` — label of a PPM code. Status / priority codes are read from the shared table
  (`lib/codeLabels.js`, SDPLabels); the map only adds the PPM-only codes (stage, kind, gate refusal, action, field,
  document type, dependency category, capacity, role). English on the page; French through the page dictionary.
- `public/lib/ppmRaidForm.js` — the pre-filled RAID form (only changed fields are sent).

## Rules checked

risk probability / impact are 1–3; no inline script on the strict pages (register, decisions, capacity).
