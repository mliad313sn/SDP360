# RFI — Request for Improvement

| Field | Value |
|---|---|
| **Ref** | RFI-YYYY-NNN (assigned by Secretary) |
| **Kind** | tracker · widget · dashboard · metric · integration · ux · data-quality · governance |
| **Title** | one line, what you want to be able to do |
| **Requester** | name, role, site |
| **Date** | |

## 1. Problem today
What hurts, how often, who is affected, what it costs (time, errors, missed decisions). Attach a screenshot or an example number if relevant.

## 2. Proposal
What should exist. For a tracker: units, items, period, who enters data. For a dashboard/widget: audience, device, metrics needed, decision it supports. For a metric: proposed formula in words, window, source fields.

## 3. Data (filled by Data Engineer at triage)
Source(s), key, refresh, PII, existing metric keys reused, new readers needed.

## 4. Scoring (Committee)
| Impact 1–3 | Reach 1–3 | Effort 1–3 | Data risk 1–3 (gate) | Priority = I×R÷E |
|---|---|---|---|---|
| | | | | |

## 5. Decision
`DEC-YYYY-NNN` — accepted / deferred / rejected — reason — target phase/sprint — owner.

## 6. Delivery & verification
Version published / commit · date · requester confirmation (`verified`) · follow-up RFIs.
