# IT Project Portfolio Reconstruction Specification

## Source workbook

**Important_Email_Action_Summary_2026-11-18.xlsx**

## Objective

Document the functionality, business rules, data structures, automation, presentation logic, dashboard components, controls, and visual-design principles contained in the workbook so they can be reproduced inside an existing application.

---

# 1. Executive Summary

Despite its filename, the workbook is effectively a **2027 IT Project Portfolio Collection, Governance, Data Quality, Capacity and Planning solution implemented in Excel**.

The solution combines five major capabilities:

1. User guidance and onboarding
2. Structured project intake
3. Portfolio management and governance
4. Management dashboard and data-quality monitoring
5. Automatic project roadmap and Gantt planning

The workbook should be reconstructed as an integrated **IT Portfolio Management module**, not as a simple spreadsheet form.

The target application should cover:

- Project intake
- Project register
- Business case
- Ownership
- Prioritization
- Budget tracking
- Risk management
- Dependencies
- Delivery effort
- Resource demand
- Data-quality controls
- Management alerts
- Decision management
- Portfolio dashboards
- Automatic timeline
- Capacity analysis
- Reporting and export
- Governance workflow

## 5.1 Identity

### Project ID

Recommended structure:

```text
PRJ-{YEAR}-{SEQUENCE}
```

Example:

```text
PRJ-2027-025
```

The identifier must be:

- Unique
- Immutable
- Generated by the backend
- Independent of sorting and filtering
- Independent of deletion
- Independent of visual row position

- Sabodala
- Hounde
- Mana
- Lafigue
- Ity
- Kalana
- Massawa
- Dakar
- Abidjan
- Ouagadougou
- Exploration
- Group / Multi-site
- Tanda

Only one primary site should own the project. Cross-site initiatives should use **Group / Multi-site**, with affected sites maintained in a separate multi-value relationship.

# 7. Business Case

## 7.1 Business Need / Problem

This field explains why the project needs to exist. It should capture:

- Operational problem
- Business risk
- Compliance requirement
- Technology limitation
- Production impact
- Safety impact
- Business opportunity
- Current inefficiency

Recommended structure:

```text
Current situation
Business impact
Problem
Required outcome
```

## 7.2 Expected Business Value

The system must separate the problem from the expected value.

Potential benefits include:

- Downtime reduction
- Production improvement
- Safety improvement
- Risk reduction
- Productivity
- Cost avoidance
- Support-effort reduction
- Compliance
- Operational resilience

Avoid vague descriptions such as “Improve IT,” “Increase performance,” or “Modernize infrastructure.”

Person or team responsible for delivery execution.

```text
Business Sponsor ≠ IT Owner ≠ Delivery Lead
```

# 10. Schedule Management

Required fields:

- Planned Start
- Planned End

Calculated duration:

```text
Duration = Planned End - Planned Start + 1
```

The system must block submission or approval when:

```text
Planned Start > Planned End
```

Quarters and placeholders such as Q1, Q2, Q3, or TBC must not be stored in date fields. Use separate indicative-quarter and schedule-confidence fields when exact dates are not yet available.

- Project name missing
- Business need missing

- IT owner missing
- Priority missing
- Start date missing

- Budget status missing
- Dependencies missing
- Key risks missing
- Decision requirement missing
- Status missing
- Delivery effort missing
- Resource demand missing or zero
- Risk exposure missing
- Delivery lead missing
- Invalid dates

## 20.1 Data Quality Score

```text
Completed required fields / Total required fields × 100
```

## 20.2 Data Quality RAG

- Green: 100%
- Amber: 80% to 99%
- Red: below 80%

Override the score to Red when a blocking error exists, such as an invalid schedule or missing accountable owner.

# 31. Existing Issues That Must Not Be Replicated

## 31.1 Filename Mismatch

The source filename suggests an email action summary, but the workbook is a portfolio tool.

Recommended module name:

- IT Project Portfolio
- IT Portfolio Planning & Governance

## 31.2 Row-Based Project IDs

The current row-driven numbering can produce duplicate or conflicting sequences.

**Correction:** Generate immutable IDs in the backend.

## 31.3 Invalid Date Types

Quarter labels and TBC values appear in date fields.

**Correction:** Separate exact dates, indicative quarters, and schedule confidence.

## 31.4 Timeline Formula Errors

Text or incomplete dates generate calculation errors.

**Correction:** Display “Schedule not baselined” until valid dates are available.

## 31.5 Currency Inconsistency

Budget values may use different currencies while the field is presented as USD.

**Correction:** Store amount, currency, conversion rate, base currency, and converted amount.

## 31.6 Resource Demand Inconsistency

Numeric FTE and categorical resource demand are mixed.

**Correction:** Store them in separate fields.

## 31.7 Row-Reference Misalignment

Timeline attributes can become associated with the wrong project because of positional formulas.

**Correction:** Use Project ID as the relationship key everywhere.

## 31.8 Fixed Range Limitation

Excel formulas rely on fixed row ranges.

**Correction:** Use dynamic database queries without predefined project limits.

## 31.9 Non-Actionable Alerts

The workbook provides alert counts but not an ownership and resolution workflow.

**Correction:** Make alerts assignable, traceable, and closable.

## 31.10 Blank, Zero, TBC, and Not Applicable

These states are not consistently distinguished.

**Correction:** Treat the following as separate values:

- Blank
- Zero
- TBC
- Not applicable
- No known dependency
- No identified risk

# 38. Final Design Principle

The workbook should not be reproduced literally. Preserve the operating model:

```text
Guidance
→ Project Intake
→ Data Quality
→ Portfolio Analysis
→ Risk and Capacity
→ Management Decision
→ Roadmap
→ Delivery
```

Replace Excel mechanics with application capabilities:

| Excel mechanism | Application equivalent |
|---|---|
| Excel formula | Business rule |
| Excel row | Project record |
| Hidden list | Master data |
| Conditional formatting | UI status / RAG |
| Dashboard formula | Dynamic KPI |
| Cell validation | Form validation |
| Timeline formula | Gantt engine |
| Alert count | Actionable alert |
| Decision field | Decision workflow |
| Workbook sheet | Application module |
| Row reference | Database relationship |
| Excel access | Role-based access control |
| Manual follow-up | Workflow and notification |
| Spreadsheet history | Audit trail |

The target should operate as a **lightweight enterprise IT Portfolio Management and Governance application** while preserving the simple, practical, site-friendly experience of the original workbook.
