# A-14 — Project record page (project.html): charter, plan with Gantt and critical path, milestones, RAID, gates, history

No new switch. Plan writes from the page follow the A-15 rule (`portfolio_editor_plan_writes`, default `0` =
committee only) and reads follow `portfolio_site_scope_reads` (default `0` = everyone reads every project).
No witness project is seeded: the fixtures in the smoke tests are fictitious; the real witness is named by the PMO.

## What was built
- Migration `db/postgres/reports/044_project_page.sql` (additive): `portfolio_tasks.progress_pct`, `effort_hours`,
  `portfolio_milestones.owner`, `portfolio_risks.kind` (`risk` default — existing rows keep their meaning).
- `services/projectSchedule.js`: `charterText()` (a JSON charter is judged on the text of its fields; plain text
  unchanged) used by the approval gate; `scheduleView(tasks, {anchor})` built on `criticalPath` (which now also
  returns its `es`/`ef` maps — additive): dates from the project start (else the earliest task start, else null =
  relative days only), slack, `critical` (slack 0), `duration_days` null + `assumed_duration` when criticalPath
  counted 1 day, task variance.
- `services/governanceStore.js`: task/milestone/risk columns + validation (progress 0..100, effort ≥ 0, kind in
  `risk|issue|assumption`); `projectDetail(id)` (single-project queries); `gateCounts(id)` shared with
  `moveProjectStage` — `GATE_OPEN_RISKS` counts `kind='risk'` only (identical today).
- `routes/governance.js`: `GET /api/governance/portfolio/project/:id` — project, tasks, milestones, deliverables,
  RAID, plan, resource conflicts, `allowed_stages` with a DRY RUN of each gate for the caller, `can_gate`,
  `can_edit_plan`, `can_see_history`; 404 when hidden by the A-15 read scope; amounts stripped unless canSeeMoney.
- `public/project.html` (new, `_htmlCache` + `sendHtmlPage`): 7 tabs (role=tablist, arrows/Home/End, `#tab` deep
  link), URL `?id=` read first, every value escaped; SVG Gantt (plan bar, hatched computed bar, dashed baseline,
  red + text "CP", finish-to-start arrows, milestones ✓/!, today line from the server's as_of, aria-label + title per
  bar) and a table view; task / milestone / RAID editors; gates with plain-language refusals; history shows
  "restricted" on 403. Extension point for A-27/B-08: `TABS` + `RENDER` registry.
- `public/portfolio.html`: project keys link to `project.html?id=`; `task` kind in the edit form (WBS, parent task,
  duration, allocation, effort, depends_on ids, progress).
- `public/rfi.html`: committee-only "Convert to project" on accepted/scheduled rows → objective/key/owner form →
  link to the new project; a 409 with `project_id` links to the existing one.
- `public/help.html` §25: "Project page" EN + FR inside the section.
