## Built
- `services/pilotMetrics.js` — pure: measure dictionary (definition + source tables per measure), business-event
  filter, ISO week, median (null when empty), HMAC pseudonym, per site × persona × week buckets, registry
  freshness share (reuses `publishGate.moduleFreshness`), Markdown and CSV (formula-neutralised) output.
- `tools/pilot/pilot-metrics.js` — CLI `--from --to [--site] [--format=md|csv|both] [--out]`; loads `.env` first,
  `require.main` guard; sets the session `TRANSACTION READ ONLY` before the first query; selects users as
  (id, role, site) only — never a name or e-mail; a missing table is reported as "no data".
- `docs/ops/pilot/` — `PILOT-MEASUREMENT.md` (who records what, when), `T1-T8-SHEET.csv`, `SUS-FORM.md` (EN/FR,
  scoring rule), `WEEKLY-REPORT-STOPWATCH.csv` (the effort measure the created→submitted proxy cannot give).

## Deviations
- "Conflicted" field entries are not stored by the server (409 answered, never written) → reported as
  "not recorded" (null), not invented.
- `action_items` have no creation time → creation = created_at of the first weekly report of the lineage
  (stated in the definition).
- UNKNOWN/stale share = registry metrics whose source module is UNKNOWN/STALE by sync freshness. Per-site
  value-null resolution needs the app's db modules, whose boot runs DDL — not read-only — so it is left out
  and said so in the output.
- No `report_config` key added: the pseudonym key is an `.env` secret (`PILOT_PSEUDONYM_KEY`).
