# C-08 — Guided dashboard composer (F17, G17)

Branch `goal/c-08`. UI change on an admin/publisher authoring page; no switch (F17 evidence: "No switch needed
(UI only)"); the draft → submit → four-eyes publish → rollback flow and its routes are untouched.

## What changed
- `public/lib/composerGuide.js` (new, UMD, pure): `INTENTS` (status · trend · compare sites · target · detail),
  `PRESETS` (7 questions), `suggestTypes`/`fitError` (intent × metric → creatable type, unfit types carry a reason;
  a trend needs a metric with history — `window_kind` ≠ `current`), `fieldsFor` (one typed field per
  `WIDGET_TYPES[type].props`: RAG policy select, window select by metric kind, series multi-select limited to
  same-unit time-series metrics (≤ 4), page size number, sources/onlyOverdue/stacked…), `renderFieldsHtml` /
  `readFieldValues` (blank = absent), S-M-L `dims`/`flowLayout`/`sizeOf`, `plainErrors`/`humanize`.
- `public/dashboard-composer.html`: guided steps question → metric (name, unit, window, formula, certification
  shown) → intent → type (suggested first, unfit options disabled with the reason) → generated fields → size;
  raw `x/y/w/h` inputs, the "RAG policy"/"Trend window" free fields and the always-visible JSON textarea removed;
  layout = append + Move up/Move down + size (flow packing, never overlaps/overflows; stored coordinates kept until
  the publisher moves/resizes/adds); the JSON options live in `<details class="advanced" hidden>` shown only to
  the admin tier (non-admins keep any stored extra keys untouched); server validation errors are rendered in plain
  words in the message list AND next to the field (`ferr-*`), with a "N to fix" mark per widget in the list.
- Server (authority): `validateDashboard` accepts `opts.metricKinds` and refuses a trend whose metric or series is
  a `current` snapshot; `dashboardStore.saveDraft` and `PUT /api/dashboards/:key` pass the registry kinds.
  Without `metricKinds` the validator behaves exactly as before.
