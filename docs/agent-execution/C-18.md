# C-18 — Access templates, requests, approvals, grants with expiry, SSO grant merge, My access screen

Goal row: PLAN-V3 V4b · findings G38 G39 G40 G50 G51(part) A02 A03 A07 A09 · migrations 057, 058 ·
switches `access_require_approval` (`0`), `access_grant_expiry_job` (`0`) — both default to today's behaviour.

## What was built
- **057_access_templates.sql** — `access_templates` + `access_template_versions` (draft | published). A published
  version is immutable: trigger `access_template_versions_frozen` refuses UPDATE/DELETE (store also refuses with 409).
- **058_access_requests.sql** — `access_requests` (REQUESTED → REVIEWING → APPROVED | REJECTED → ACTIVE → EXPIRED |
  REVOKED), `access_request_events` (append-only + hash chain via `sdp_append_only` / `sdp_hash_chain`, added to
  `services/auditChain.js` so `audit.chain_verify` covers it), `access_grants` (why / until when a role or a site is
  held; `held_before` records a role/site already held when the grant activated).
- **services/accessRequestLifecycle.js** (pure) — transitions, separation of duties (approver = super_admin, never the
  subject, never the requester, never an active deputy of either), `scopeKey` binding the approval to
  subject × roles × sites × dates, request/template validation (no `super_admin` ever requested), `planRemoval`,
  `rolesRequiringRequest` (C-17 `requires_request`, through the hierarchy).
- **services/accessStore.js** — templates (create, draft, publish, retire), requests, decisions under `FOR UPDATE`,
  activation in ONE transaction writing `access_grants` + `user_roles`/`user_sites` through `rdb.updateUser`, identity
  log (`system_log` category identity, `request_id`, `grant_ids`, `valid_to` — A03), revoke/expiry removing a role only
  when no other live grant and no earlier direct source holds it, `runExpiry` (ends expired, activates approved on
  their start day).
- **routes/access.js** — `GET /api/access/me`, templates CRUD + publish/retire (super_admin, guard tagged for C-17 →
  `platform.identity.manage`), `POST /api/access/requests`, `POST /api/access/requests/:id/{review,approve,reject,revoke}`,
  `GET /api/access/requests/:id`, `GET /api/access/approvals`. Every error through `httpError.fail`.
- **Admin ▸ Users** (`routes/adminUsers.js`) — with `access_require_approval='1'`, adding a role that opens a
  `requires_request` capability (today: admin, executive, finance-viewer; super_admin too) is refused 409 without an
  APPROVED/ACTIVE request; explicit super_admin break-glass `{break_glass:true, break_glass_reason}` passes and is
  logged `access_break_glass` risk=1. `'0'` = unchanged.
- **Job** `access.grant_expiry` (03:50, internal, optional) in `services/sync/jobs.js`; self-skips unless
  `access_grant_expiry_job='1'`.
- **SSO trap** (`services/ssoProvisioning.js`, `services/ssoLogin.js`) — the group map now merges back roles held by a
  live access grant; the five newer roles (site-business, dashboard-publisher, committee-member, field-tech,
  finance-viewer) are mappable; an unreadable grant table skips provisioning for that login instead of stripping.
  **Found while testing**: the provisioning update passed only `{roles, role}` to `rdb.updateUser`, which rewrites
  `full_name`/`site_id`/`active` from its arguments → on PostgreSQL the NOT NULL `full_name` made every group update
  fail (silently caught). The update now carries the current name/site/active.
- **Screen** `public/access.html` + `access.js` (tabs My access · Requests · Approvals · Templates; EN/FR toggle,
  self-translated; boot cache + `sendHtmlPage`) and a **Request this access** button on `no-access.html` pre-filling
  roles + page.
