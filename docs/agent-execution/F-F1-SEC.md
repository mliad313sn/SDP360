## Deviations from the goal text

1. F-ARCH-02: the goal names `_requireSuperAdminInline`; the route uses the `requireSuperAdmin` middleware instead so the generated authorization matrix shows the role guard. A 30 s cool-down was added because the Analytics export downloads the whole view whatever `maxRows` says; a response cap alone does not limit that cost.
2. F-ARCH-03: `tools/installer/Manage-SDP.ps1` has no status command (it handles backup, restore and schedules). The identity block was added to `tools/sdp-manager.js status` / `status --json`, which is what the Windows Manager reads. The PowerShell file is unchanged.
3. F-ARCH-03: the `sbom` block has a third field, `matches_manifest` (true / false / null), besides `present` and `sha256`. `consistent` is false when the signature does not verify or the SBOM differs from the manifest, not only on a version mismatch.
4. F-ARCH-03: the release SBOM no longer carries a timestamp (it must be byte-identical to the one hashed in the manifest).
5. F-ARCH-04: the My work surface is asserted as "never lists a hidden project", not as equality: its benefit reviews are per site card, so a group-level project or an owner-by-text project is not listed there. History is asserted for money readers only (others get 403 on every project by role).
6. F-ARCH-06: the committed `CSP-JOURNEYS.md` is built from files only (journey table + page scan), so `--check` is deterministic. Violation counts are added on demand from a System Logs JSON export (`--violations <file>`); the tool does not read the database. The setting is applied within 30 s through a cache, not through a hook on the settings route.
