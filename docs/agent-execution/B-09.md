# B-09 — Roadmap Manager → portfolio single source

Goal source: corrective playbook PO-REVIEW §C "B-09" (audit P1-17) and the human-gate row
"Roadmap cut-over (B-09): redirect after one parity cycle; deletion via CAB" (PMO + PO + CAB).

## What was built

| Piece | File | Behaviour |
|---|---|---|
| Parity engine (pure) | `services/roadmapParity.js` | Compares one user's `roadmap_objectives` / `roadmap_deliverables` with the portfolio programme `itsm-roadmap` created by `POST /api/governance/roadmap-migration`: objective present, name / weight / progress / target date / mapped status, deliverables matched by name (missing, extra in portfolio, status or due-date difference), extra portfolio objectives. Verdict `not_migrated` · `in_parity` · `drift`. Markdown renderer. |
| Read-only CLI | `tools/governance/roadmap-parity.js` | `node tools/governance/roadmap-parity.js [--user=<id>] [--json] [--out=f.md] [--strict]`. One `BEGIN READ ONLY` transaction, always rolled back. Reads the tables directly (NOT `getRoadmap`, which lazy-seeds = writes). `--strict` exits 2 when any user is not in parity. |
| Switch | `services/reportConfig.js` `roadmap_redirect_to_portfolio` = `'0'` | `'0'` = today (editable Roadmap Manager). `'1'` = read-only. Read per request; a failed config read falls back to `'0'`. |
| Route guard | `routes/roadmap.js` | `readOnlyGuard` after the auth gates on all 13 write routes (PUT/POST/DELETE) → 409 `{read_only:true, portfolio_url}` when the switch is `'1'`. New `GET /api/roadmap/mode` and `GET /api/roadmap/parity` (super_admin, read-only). |
| Page | `public/itsm-roadmap.html` | Hidden banner "Lecture seule … le portefeuille" with a link to `/portfolio.html`; shown only when `/api/roadmap/mode` says read-only; edit controls made inert (CSS + capture-phase event block), CSV export and tabs stay usable. The server 409 is the enforcement. |
| Pilot profile | `docs/ops/pilot/PILOT-PROFILE.md` | Row `roadmap_redirect_to_portfolio` built, default `0`. |

Nothing deletes roadmap data. No migration was needed (050 unused). `routes/governance.js` and the
project page were not touched (A-27 area); the two mappings the parity repeats from the migration route are
pinned by a test that reads the route source, so a change there fails loudly.

## Tests

`tests/roadmap-parity.test.js` — 11 tests (PostgreSQL): pure verdicts (not migrated / in parity / drift with
each kind of difference), mapping pin against the migration route, CLI args, default switch + pilot profile,
page markers; end to end: seed roadmap → CLI `not_migrated` (exit 2 strict) → real migration route →
`in_parity`, row counts unchanged by the CLI, `/api/roadmap/parity` agrees → roadmap edit → `drift` → switch
`'1'`: 7 write routes 409, row counts unchanged, reads still work → switch back `'0'`: editable.

Runs: roadmap-parity 11/11; roadmap.smoke, readme-truth, governance-routes.smoke, ppm-project-lifecycle.smoke,
await-precedence, roadmap-evidence, roadmap-training 57/57; report-config-uplift, html-pages-before-static,
i18n-coverage 32/32. 0 fail, 0 skipped. ESLint clean on touched JS.
