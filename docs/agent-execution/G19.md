# G19 — Field offline PWA, conflict-safe sync and on-site adoption

Lead: sdp-field · independent review: sdp-field-architect (AI specialist persona).

## Defects found (both caused silent data loss)

1. **Phone**: `public/field/app.js` deleted a queued entry on ANY non-5xx answer — including **401** (expired
   session: the technician signs in again and the inspection is gone), 400/403 refusals and 409 conflicts.
2. **Server**: after a transient 500 the outbox row stayed `failed`, and every retry answered "duplicate" — the
   phone then deleted the entry without it ever being applied. Two simultaneous sends of one entry (two tabs, a
   retry during a slow apply) could also both apply it.

## What was built

## Independent review (sdp-field-architect persona) — outcome and fixes

Verdict on the first pass: silent-delete fixed, but "no silent loss / exactly once" not yet proven. Fixed since:
- "Send again" swapped delete-then-put (two transactions) for **one** transaction (`obSwap`).
- A conflict whose original was **already applied** is marked "déjà appliqué (version précédente)" — Discard only;
  re-sending would have applied twice. A refused entry warns that sending it unchanged will be refused again.
- Claim token in its own columns (migration `042_field_claim.sql`); `finish` only writes while holding the claim;
  stale window **15 min** (above the 5 min IIS proxy timeout); **tickets and actions are never re-claimed
  automatically**; a ticket whose SDP outcome is unknown is refused "check ServiceDesk Plus" instead of retried.
- One failing entry (photo 4xx, proxy HTML page, network) no longer blocks the queue: per-entry error handling;
  a 401 during a photo upload stops the sync with the session message; the upload id is stored before the chunks.
- Field action buttons: queued before the action leaves the list, errors shown, double tap ignored.
- Shared phone: cached data keyed by user, a service-worker answer of another user refused, legacy unkeyed cache
  dropped, logout clears the field cache (never the outbox); entries without an author shown "auteur inconnu —
  à vérifier", never sent automatically ("Envoyer en mon nom" is an explicit choice).
Not fixed: a route-level test with a slow or throwing apply stub (store-level tests cover the claim); the browser
harness is not in CI.

## Browser evidence (Playwright, 390 px, throwaway PostgreSQL, network simulated — not a real device)

Double tap → 1 entry · offline → kept · back online with an expired session (401) → kept, message
"Session expirée — reconnectez-vous. Rien n'est perdu…" · refusal (400) → kept as "refusé" with the reason, not re-sent
on the next sync · "Renvoyer" → applied by the real server and removed ("Envoyé : Inspection …").

## Second security review (sdp-ciso persona, AI) — fixed

Photo references can no longer point at another inspection (threat model rows 13-14); entries keep their author and
are refused under another session (row 15); an unknown ticket outcome is shown as "to check" and never re-sent
(row 16); logout clears the shared-phone caches (row 19).
