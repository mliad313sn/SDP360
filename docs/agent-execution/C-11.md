## What changed

- **`public/lib/dashboard-shared.js`** (pure helpers, exported on `window`):
  - `helpdeskCategoryKey(r)` — Category, else Sub Category (same order as the Top-10 chart); empty or `-No Value-`
    is kept as `(No category)` instead of being dropped, so the Pareto total equals Inbound.
  - `paretoRows(rows, keyFn, {top})` (`dashboard-shared.js:258`) — counts sorted desc (ties by key), the first `top`
    (10) as their own bar, every remaining key folded into ONE `Other (k)` bar carrying their **full** count (never an
    "Other" of a single key, which would hide its name); `pct` and `cum_pct` (last = 100). Σ n = total = rows.
  - `slaRanking(rows, keyFn, {minN})` (`:297`) — resolution SLA % per key on the **tile's rule** (pStats:
    closed = `isClosed`, violated = closed AND `isResOverdue`, `pct = round((1 − v/c)·1000)/10`, null when nothing
    closed). `ranked` = keys with ≥ `minN` closed tickets, worst first (ties: larger n, then key); `low_sample` =
    the rest, shown with n and no rank. Σ closed over both lists = `total.closed`.
  - `helpdeskSiteKey` / `helpdeskGroupKey` (empty → `(Not set)`), `rowsForKeys` (drill filter), `MIN_SLA_RANK_N`.
- **`public/index.html`** — new row `#hdAnalytics` (`:364`) between the Ageing/Top-10 row and the volume trend:
  - **Category Pareto** (`renderPareto`, `:1219`) through the A-22 `TrendPanel`: counts on the top panel,
    cumulative % on its **own** panel below (no dual axis), header shows "N tickets · K categories", the note states
    what "Other (k)" contains. Clicking a bar → `openParetoDrill` (`:1243`) → existing `_openTicketDrillModal` with
    exactly that category's tickets (for Other: all its member categories, listed in the context line).
  - **Resolution SLA % ranking** (`renderSlaRanking`, `:1265`) with a Site/Group selector: rank, key, closed (n),
    missed SLA, %; low-sample rows below, labelled "low sample", unranked; a note gives the all-sites figure, its
    n, and says it is the same rows as the Resolution SLA % tile. Rows are focusable (`tabindex=0`, Enter/Space).
    Clicking a row → `openSlaRankDrill` (`:1297`) → the drill modal with that site's/group's **closed** tickets
    (the ranking's denominator), missed-SLA first.
  - Both called from `renderAll`, so every filter/period change redraws them.

## Decisions and deviations

- **Low-sample threshold — PROPOSAL, owner to confirm.** No helpdesk sample threshold existed (the only ranking
  thresholds in the code are `MIN_RANKED_ASSETS = 20` for asset effort and `OU_MIN_N = 5` for OU learning — different
  populations). Chosen: `MIN_SLA_RANK_N = 10` closed tickets in the period (one constant in `dashboard-shared.js`).
  At 10, one late ticket moves a site by 10 points; below it a site is shown with its n but not ranked.
- **Reconciled with the tile, not with `periodSlaRates`.** The goal text cites `periodSlaRates`; but the tile
  (`pStats`) keeps **cancelled** closed tickets in the resolution denominator, while `periodSlaRates` (trend chart,
  A-17a) excludes them. Where the two differ, the ranking follows the tile, because the requirement is that the
  ranking reconciles with the tile for the same filter. The divergence tile ↔ trend is pre-existing and is listed below.
- **Monthly view:** `renderAll` replaces the tile's Resolution SLA % with the Zoho monthly summary figure when one
  exists (`_zohoSlaPct`). The ranking cannot be split from that summary, so it stays row-based and its note prints both
  figures ("…same rows as the tile (the monthly tile shows the Zoho summary figure, X%)"), rather than silently
  disagreeing.
- **Site key = the raw `Site` field.** Like the tiles' Site filter, the ranking uses the free-form SDP site label
  (no alias folding) so it splits exactly the tile's rows; "HOUNDE" and "Hounde Mine" would show as two rows.
- No switch: additive panels, no change to existing figures; strings are English like the rest of `index.html`
  (the page is on the i18n UNTRANSLATED list; `i18n-coverage` green).
