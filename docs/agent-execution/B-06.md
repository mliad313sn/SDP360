# B-06 — Field app storage durability (audit P1-16)

## What changed
- `public/field/storage.js` (new, pure UMD): `makeGuard(navigator.storage)` → `ensurePersist()` asks for
  persistent storage at most once per page (concurrent calls share one request; already-persistent → no ask;
  no StorageManager → `null`, never a throw) and `usage()` → `{usage, quota, ratio, warn}` with `warn` above
  70 %, `null` when the browser cannot tell (never 0). `isQuotaError(e)` recognises QuotaExceededError,
  Firefox's NS_ERROR_DOM_QUOTA_REACHED and legacy codes 22/1014.
- `public/field/app.js`:
  - `tx()` now rejects on transaction **abort** (`t.onabort`): a real quota failure in IndexedDB aborts the
    transaction rather than firing `onerror`, so the old promise could hang forever and the write vanished.
  - `queue()` requests persistence on the first queued entry, shows usage in `#storage-warn` above 70 %, and on
    a failed write shows "NOT saved — this phone is out of storage space…" (with the entry label), then rejects
    so the caller does NOT clear the form; earlier entries are untouched.
  - The pending-count badge is rendered at boot from the local outbox (via `setNet()`), so it shows offline
    even when bootstrap has no cache; `renderOutbox` no longer leaves an unhandled rejection.
- `index.html`: `#storage-warn` status line + `storage.js` script; `sw.js`: `storage.js` precached,
  cache bumped `field-v3` → `field-v4`; `i18n.js`: French strings for the new messages.

## Tests
- `tests/field-storage-guard.test.js` (6): persist idempotent (concurrent + repeated), already-persistent, refusal
  not retried, missing API, usage threshold / null quota, quota detection, wiring.
- `tests/field-storage-browser.test.js` (1): real Chromium (Playwright), stubbed `QuotaExceededError` on the
  outbox put → "NOT saved" error, form kept, earlier entry + badge (1) kept, persist called once, 80 % usage
  warning, badge re-rendered after an offline reload. Fails against the previous `app.js` (verified).
- Run: field-*.test.js, pg-field-store, meeting-status-options, a11y-static, business-only-boundary,
  inspection-blob-refs, await-precedence — 64 pass / 0 fail / 0 skip.
