## 4. Three tasks per profile, reachable from the landing page (step 4)

Task list: `tests/e2e/fixtures/profile-tasks.js` (11 profiles × 3 tasks, FR + EN; AI proposal, D-P09-4). Journeys
`tests/e2e/p09-profile-tasks-a.spec.js` (administrator, executive, business, operations, coordinator, field) and
`-b.spec.js` (pmo, finance, governance, analyst, reader): synthetic accounts on a throwaway database, workspace
profiles on, login through the real page, then each task page must be a shortcut on Home (or the landing page itself)
and open with HTTP 200, no page error, no bounce to login. Every task is **one click** from Home (well under three).
Two slices because the login throttle allows 10 sign-ins per 15 minutes per address.

Result: both slices **passed twice** (runs 1 and 2, artefacts written, 0 external requests). This proves
reachability, not that a person can complete the task — that is S8 of the runbook.

**Findings (real, in the product):**
- **F1** — an account whose only role is `audit-viewer` gets the *governance* profile by default, but
  `policies.html` (one of its destinations) needs `admin` or `committee-member`: Home shows 2 of its 3 shortcuts.
- **F2** — an account whose only role is `dashboard-publisher` gets the *analyst* profile, but `analytics.html`
  needs `admin` or `scorecard-viewer`: 2 of 3 shortcuts.
  No access is widened; the fix is a presentation choice (destination list or default profile) for the product
  owner (D-P09-7). The journeys use an account that holds the full role set and chooses the profile.
