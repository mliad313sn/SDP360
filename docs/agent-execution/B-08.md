# B-08 — Minimal benefit record on portfolio projects (catalogue A09)

No new switch: no project carries a benefit today, so nothing changes until someone records one. Funding requests
and period allocation are out of scope (Finance first says what they need).

## What was built
- Migration `db/postgres/reports/056_portfolio_benefits.sql` (additive): table `portfolio_benefits` — several
  benefits per project (deviation from the goal's "on portfolio_projects": one row per expected benefit is more
  faithful to a charter that lists several benefits; nothing on `portfolio_projects` changes). Columns: description,
  measure, unit, `value_kind` (`quantity` default | `money`), currency, baseline/target/realised values, owner (free
  text like every PPM owner), review date, evidence link, realised by/at, verified by/at.
- `services/portfolioBenefits.js` (pure): `benefitState` (planned · review_due · awaiting_verification · verified),
  `isReviewDue` (review date reached and not verified), `visibleBenefit` (money values removed for a non-money reader),
  `evidenceLinkOk` (http/https only), `reviewItems` (obligation lines, never a value in them).
- `services/governanceStore.js`: `benefit` entity in the generic portfolio upsert/delete (so the plan-write gate and
  `planRow` apply), `recordBenefitRealised` (clears any verification; ledger `benefit_realised`), `verifyBenefit`
  (403 `SELF_REVIEW` when the verifier entered the value — the A-25 four-eyes pattern; 409 `NOT_REALISED`; ledger
  `benefit_verified`), a change of measure/unit/kind/currency/baseline/target after verification clears it (ledger
  `benefit_unverified`), `dueBenefitReviews({siteId, asOf})` (primary or extra project site), benefits in
  `portfolio()` and `projectDetail()`.
- `routes/governance.js`: `benefit` joins `PLAN_KINDS` (committee; site editors only when `portfolio_editor_plan_writes`
  is on); a money benefit is written only by a money reader (403 `MONEY_SCOPE`); `POST /api/governance/portfolio/benefit/:id/{realised,verify}`;
  project detail / portfolio / workbook strip money benefit values unless canSeeMoney. `services/portfolioAccess`
  filters benefits with the A-15 read scope.
- A09 reminder (no outbound send): register `benefit_review` in `services/obligations.compose` (`registers.benefit_reviews`,
  null = not read) fed by `routes/obligations.js`; a `benefit_reviews` block on "My work" (`services/myWork`,
  `routes/myWork`, `public/lib/home-page.js` EN + FR); label in `public/lib/obligations-page.js` EN + FR.
- `public/project.html`: Benefits tab via `TABS`/`RENDER` (list with state pills, hidden money values, evidence link
  only when http(s), Verify button hidden for the person who entered the value, definition editor, realised-value
  form). Stays on the i18n untranslated list.
- A-27 workbook: a `Benefits` sheet (money values only for a money reader). The deck is unchanged (golden kept).
- Catalogue A09 `missing` → `partial`; `REPORT-ALERT-CATALOGUE.md` regenerated; help §25 EN + FR (eight tabs).
