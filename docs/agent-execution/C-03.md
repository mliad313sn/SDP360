# C-03 — Role resolver: skip inactive / site-less holders and deputies (finding A10)

Switch: governance **policy** `governance.skip_inactive_holders` (services/governancePolicy.js PARAMS; platform only,
protected, default `false` = today). Documented in docs/sdp360/completion/GOVERNANCE-POLICIES.md and
docs/ops/pilot/PILOT-PROFILE.md (non-`report_config` list — recommended pilot value `true`, proposed, not approved).

## What changed
- `services/governanceRoles.js` — pure resolver takes OPTIONAL `opts = { active:Set, sitesOf:(id)=>number[]|null }`
  (null sites = admin tier, unscoped). Without `opts` every function is byte-for-byte today's behaviour.
  With `opts`: `holders()` drops inactive holders and site rows whose site the person no longer holds, falling back
  to eligible platform holders; `escalationTarget()` replaces an ineligible holder by their eligible deputy, skips
  deputies that are inactive or no longer share a site with the principal (the naming rule re-checked today), falls to
  the next matching matrix rule (`fallback_from`) and reports a gap only when nobody eligible remains; it lists the
  accounts passed over (`skipped`). `coverageGaps()` counts eligible holders only and lists `inactive_holder` /
  `inactive_deputy` entries with a reason (`inactive` / `site_removed`).
- `services/governanceRolesStore.js` — `resolverOpts()` reads the policy and, when on, `users` (active, site, legacy
  role), `user_sites` and admin-tier `user_roles`; `escalationTarget()` (used by both escalation jobs through
  services/escalationRouting.js) and a new `coverageGaps()` pass them.
- `routes/governanceRoles.js` (GET roles gaps) and `routes/policies.js` (oversight `role_gaps` + CSV wording) pass the
  store's opts; `public/lib/policiesRoles.js` labels the two new gap kinds (EN/FR).
