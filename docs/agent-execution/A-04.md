# A-04 — evidence (2026-11-04, sandbox, Linux, throwaway PostgreSQL)

Every .env and secrets check of an update/repair now runs before the first change; the repaired .env is
written before the sdp-manager update so its pre-update database backup sees SDP_BACKUP_KEY and is encrypted.
Step 1 (bootstrap copies services/configSecrets.js + services/apiKey.js) was already done in 776262c.
Nothing here ran on Windows, a TEST or a production server.

## Order in tools/installer-v2/post-install.js main() (update / repair / new-with-existing-.env)

preflight (A-01) → planEnv: secretsKeyGuard on the ORIGINAL .env (pg from the staged --node-modules when it
carries pg, else DIR/node_modules), then envPreflight in memory (writeEnvText + repairEnvText), refusal if
envProblems → `touched = true` → writePlannedEnv (previous .env kept as .env.before-setup-<stamp> when a key
was replaced/generated) → step 1 swapNodeModules → step 2 sdp-manager update (backup) → … A refusal in planEnv
leaves .env byte-identical ("nothing was changed", exit 1); a later failure restores envBefore in the catch.
