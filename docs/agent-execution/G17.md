## Evidence (automated — not user validation)

Playwright, Chromium, throwaway PostgreSQL, super_admin session (harness in the session scratchpad, not in CI):
- 1280 px: Operations caret by keyboard → `aria-expanded=true`, focus on Inspections, headings Governance / Plan & track /
  Report & share / Configure; Escape → menu hidden, `aria-expanded=false`, focus on the caret; ArrowUp → Field app (last);
  Tab ×2 → menu closed.
- "/" does nothing; Ctrl+K focuses the finder; "insp" → "1 page found" in the live region; ArrowDown → first result;
  Escape → focus back on the Find button.
- 390 px sweep: 0 page with horizontal overflow (before: activity-tracker 231 px, executive-report 870, help 823,
  index 876, it-review 551, itsm-integrations-plan 684, meetings-insights 241, system-logs 235, reports 195).
- help.html: 42 tables wrapped in `role=region tabindex=0` scroll boxes.

Not shown by this evidence: what a screen reader actually announces, and whether users find their way faster.

## Independent review (sdp-ux-lead persona) — outcome

First pass: **FAIL for AA**. Fixed: "/" single-key shortcut removed (WCAG 2.1.4); hover/focus-within opener vs
`aria-expanded` mismatch and Escape on hover menus (4.1.2, 1.4.13); invisible focus ring in the finder (2.4.7);
finder focus return, live count, arrow keys, Tab-out; super_admin landing on the Executive workspace; breadcrumb
section linking to a sibling page; `display:block` tables (1.3.1) and unfocusable scroll boxes (2.1.1); pre-existing
focus stop with no role on the menu wrapper; `aria-haspopup` removed (disclosure, not menu).
Known limitation (not a fix): `it-review.html` keeps the author's desktop layout and scrolls inside its own box on a phone.
