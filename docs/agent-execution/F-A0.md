### Holes found

- **None** in the server's role guards, site perimeter, métier lock, freezes or money masking of assets: every probe
  matched the committed matrix on the first full run (the only mismatches were the harness's own feature-switch 404s,
  fixed by arming functional switches in the test world).
- **D1 — KNOWN DEVIATION (not changed, policy decision pending: may committee-member see money?)** — invariant 2 says
  amounts are visible only to the admin tier + finance-viewer, but `routes/governance.js` `canSeeMoney = isCommittee ||
  finance-viewer` (`routes/governance.js:62` + `:502`, G12): a `committee-member` WITHOUT admin / finance-viewer reads the
  portfolio budget on the project detail, the portfolio list, `report.html` and the budget periods. Asset amounts (G-11)
  are not affected. Kept as an explicit expected-fail list (`KNOWN_MONEY_DEVIATIONS` in `tests/_rbac-matrix-core.js`):
  any OTHER money violation fails, and if the deviation stops reproducing the test fails too, so the decision must be
  recorded here when it is taken. Owner: PO / IAM owner.
- **Dark write path (invariant 7)** — `services/sdpApiClient.js:118-121` `createRequest` exists and is reachable through
  `PUT /api/field/outbox/:uuid` (`kind: ticket`) only when `sdp_api_write_enabled = '1'`. Pinned off (see above); not removed.

## 4. Rollout note

No switch — it is a CI gate (`npm test`, already in `.github/workflows/ci.yml`). Owner: **release manager**. Per release:
`git show <last-tag>:docs/ops/authz-matrix.json > /tmp/old.json && node tools/agent/authz-diff.js /tmp/old.json docs/ops/authz-matrix.json`
and review the "ACCESS WIDENED" block before sign-off. When a guard changes on purpose: regenerate the JSON, review the diff, commit both.

## 5. Value metric

- **Permission regressions per release** — target 0 reaching `main`: any guard / role / scope / freeze / money / métier
  change now fails CI unless the committed matrix is regenerated (and the diff reviewed). Measure: count of
  `authz-diff` widenings per release + count of red CI runs on `rbac-*` files.
- **Enablement lead time** — arming a switch (e.g. `portfolio_editor_plan_writes`, `access_recert_enabled`) no longer needs a
  manual RBAC review of the whole surface: the world arms every functional switch and the sweep runs green. Measure: days
  from "switch requested" to "switch armed" before/after.
