# Anonymised snapshot — operator procedure

Status: tool built and tested on synthetic data only (E-D06 + E-Q02, expert audit of 5 Nov 2026).
**No anonymised extract exists and none is approved.** Lifting the ten `no prod-snapshot` skips
(`tests/.skip-allowlist.json`) is the data owner's act, not an agent's.

## Who may run it

Only the **data owner**, or an operator the data owner names, on a machine that is allowed to hold production
data. An agent never runs it on real data and never opens the result.

## Steps

1. Restore a production dump into a **new, separate** database (e.g. `sdp_snapshot_copy`) — never the live one.
2. Choose a key of 16+ characters and keep it with the operator (not in `.env`, not in the repository). The same
   key gives the same pseudonyms; a new key gives new ones.
3. Dry run first:
   `SDP_ANON_KEY=… node tools/data/anonymize-snapshot.js --db=postgres://…/sdp_snapshot_copy --confirm-copy=sdp_snapshot_copy --dry-run`
4. Real run: the same command without `--dry-run`.
   - Exit `0`: committed. Exit `2`: **refused** — an e-mail or phone pattern remained; the transaction was rolled
     back; the report lists `table.column` and a count (never a value). Add a rule for that column and re-run.
   - The tool refuses when `--confirm-copy` is not exactly the database name, or when the name is the database of
     the `.env` `PG_URL` (production).
5. Read the report's **"Columns not covered"** list: those columns were kept as they are. A person's name written
   in one of them cannot be found by a pattern — the data owner decides whether each is acceptable.
6. The data owner approves (or rejects) the extract in writing. Only then may it be dumped and handed to a
   developer, who runs `SDP_SNAPSHOT=1 SDP_TEST_PG_URL=<url> node --test tests/review-data.test.js tests/site-window-readers.test.js`.

## What it changes

| Kind | Columns (examples) | Becomes |
|---|---|---|
| person | users.full_name, request_records.technician / requester, md_issues.champion, insp_inspections.inspector_name, system_log.actor | `Person <hmac>` (same person → same pseudonym everywhere) |
| username | users.username | `user-<hmac>` |
| e-mail | every column whose name contains `email` | `user-<hmac>@anon.invalid` |
| free text | subjects, descriptions, notes, comments, observations, priorities, attendees | `Text <hmac>` |
| ticket id | request_records.request_id / display_id, change_records.change_id / display_id (+ the tables that reference them) | keyed pseudonym (numeric ids stay numeric) |
| JSON | udf_json, state_json, system_log.details, incubation_json | keys, dates, numbers and structural keys (priority, status, site…) kept; other strings replaced; `data:` URLs removed |
| removed | photos / signatures / attachments (`*_b64`), `system_log.ip`, password hashes, `report_config` secrets, `sessions` rows | NULL / `anonymised` / blank / deleted |

Kept: row counts, ids used for joins (other than ticket ids), dates, statuses, codes, site names, currencies.

The full rule list is `RULES` in `tools/data/anonymize-snapshot.js`; tests: `tests/anonymize-snapshot.test.js`.
The synthetic organisation `tests/fixtures/reference-org/` (generated by its `generate.js`) exercises the readers'
shape without any real data (`tests/reference-org-shape.test.js`).
