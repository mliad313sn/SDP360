## Goal

Fork the **self-contained weekly/monthly report-editor data layer** of `reports.db`
(manually entered/edited content — no Zoho coupling) to PostgreSQL behind the existing
`REPORTS_BACKEND=postgres` flag, reusing `services/pgDb.js`. Default backend stays `sqlite`;
the fork is no-op-dispatched so prod is unchanged until an operator flips the flag.

This is the 🟡 medium sub-chunk of Chunk 4. It excludes the hot read path / Zoho sync /
aggregate assemblers (Chunk 4D).

## Scope — functions forked

All behind `REPORTS_BACKEND === 'postgres'` dispatch (sqlite path untouched):

| Family | Functions |
|---|---|
| Weeks | `ensureWeek` only |
| Report header | `ensureReport`, `getReport`, `listReports`, `deleteReport`, `updateReportStatus`, `touchReport`, `getWeekSummaryData` |

| Monthly edits | `getMonthlyReport`, `getMonthlyEdits`, `saveMonthlyEdits` |
| Objectives | `getAnnualObjectives`, `saveAnnualObjectives` |

> **PURE — NOT forked:** `getISOWeek(date)` and `getWeekRange(year, week)` are pure date math
> (`reports-db.js:617`, `:629` — `getWeekRange` uses `_zFirstSun`, it does NOT query `weeks`).
> `getPreviousWeek` (`:652`) is pure too (calls `getISOWeek`). They stay synchronous and are
> called by the pg branches without `await` (e.g. `getWeekSummaryData` reads `getWeekRange(...)`
> synchronously). Only `ensureWeek` (`:642`) touches the DB.

**Out of scope (Chunk 4D):** `getMonthlyData` (assembler — calls `getCalendarMonthlyHelpdesk`/

`getHelpdesk6MonthHistory` / `getMonthlyHelpdeskHistory` / `*DB` aggregate, `upsert*Batch`
(Zoho writers), `cab_approvals`, `change_records`, `request_records`, `survey_*`,
`sync_metadata` helpers (`getSyncStatus`/`getLastSyncAt`/`markSync*`), `getCABMetrics`,

## Schema

New migration `db/postgres/reports/003_reports.sql` (idempotent, `IF NOT EXISTS`), applied by
`initPgReports()` after `001_auth.sql` + `002_config.sql`. Ten tables:

- **`weeks`** — IDENTITY id, year/week_number INTEGER, start_date/end_date/label TEXT, UNIQUE(year, week_number).
- **`weekly_reports`** — IDENTITY id, site_id INTEGER → sites(id), week_id INTEGER → weeks(id),
  status TEXT, submitted_at TEXT (app), submitted_by INTEGER, **created_by INTEGER** (ALTER at
  `reports-db.js:353`), created_at/updated_at TIMESTAMPTZ, UNIQUE(site_id, week_id).
- **`infra_kpis`** — IDENTITY id, report_id → weekly_reports(id) **ON DELETE CASCADE**,
  service/kpi/target/status_value/status_color/trend TEXT, sort_order INTEGER.
- **`helpdesk_data`** — IDENTITY id, report_id → weekly_reports(id) ON DELETE CASCADE **UNIQUE**,
  the REAL timing columns (time_to_assign/_prev, first_reply/_prev, resolution_time/_prev,
  closing_time/_prev → `double precision`), the TEXT columns (comments_metrics, comments_sla,
  **tech_on_break, techs_on_duty**, sla_violations, group_metrics, all_groups, selected_group,
  chart_data, fetched_at — all TEXT/JSON), updated_at TIMESTAMPTZ.
- **`lights`** — IDENTITY id, report_id → weekly_reports(id) ON DELETE CASCADE, type/content TEXT, sort_order INTEGER.
- **`action_items`** — IDENTITY id, report_id → weekly_reports(id) ON DELETE CASCADE,
  task/priority/due_date/owner/status TEXT, sort_order INTEGER, **department TEXT, comment TEXT**
  (ALTERs at `reports-db.js:327-328` — read/written by saveActionItems/getActionsForReport/
  getMonthlyEdits/getPreviousWeekOpenActions; MUST be in the pg schema + copy column list).
- **`monthly_reports`** — IDENTITY id, site_id → sites(id), year/month INTEGER, edited_lights/edited_actions/notes TEXT (JSON), status TEXT, updated_at TIMESTAMPTZ, UNIQUE(site_id, year, month).
- **`annual_objectives`** — IDENTITY id, site_id → sites(id), year INTEGER, objective/target/status TEXT, sort_order INTEGER, updated_at TIMESTAMPTZ.
- **`site_module_codes`** — composite PK (site_id, module), site_id → sites(id) **ON DELETE CASCADE**, module/code TEXT, updated_at TIMESTAMPTZ. Indices on module, code.
- **`infra_kpi_catalog`** — IDENTITY id, service/kpi/target_default TEXT, display_order/active INTEGER, created_at TIMESTAMPTZ, UNIQUE(service, kpi).

Type recipe (matches 4A/4B): AUTOINCREMENT→`INTEGER GENERATED BY DEFAULT AS IDENTITY`;
`datetime('now')` DB-managed timestamps→TIMESTAMPTZ; app-supplied dates (start_date, end_date,
submitted_at, due_date, fetched_at)→TEXT; JSON blob columns→TEXT (byte-identical round-trip);
sqlite `REAL`→pg `double precision`. `sites` is NOT re-declared (owned by `001_auth.sql`).

### Seeding (in `initPgReports`, after schema)

Both catalog seeds are **data-dependent backfills** that no-op on a fresh/empty pg DB, exactly
like the sqlite boot path:
- `site_module_codes` — from `_SITE_MODULE_CODES_SEED` (canonical site-name → {module→code}),
  resolving site_id by `lower(name)=lower(?)`. Seeds nothing until matching sites exist in pg
  (they arrive via `copy-reports-auth`); `INSERT … ON CONFLICT (site_id, module) DO NOTHING`.
- `infra_kpi_catalog` — `INSERT … SELECT service, kpi, MAX(target) FROM infra_kpis GROUP BY …
  ON CONFLICT (service, kpi) DO NOTHING` (empty on a fresh DB).

The default-sites seed itself is **not** added here (sites come from `copy-reports-auth` / 4A);
tests create sites via the forked `createSite`.

## Structural note — `db.transaction(...)` helpers

`saveInfraKpis`, `saveLights`, `saveActionItems`, `saveAnnualObjectives`, and `deleteReport` are
module-level `const x = db.transaction((…) => {…})` objects (not plain functions). Each is
converted to:

```js
function saveInfraKpis(report_id, kpis) {
  if (REPORTS_BACKEND === 'postgres') return _saveInfraKpisPg(report_id, kpis);
  return _saveInfraKpisSqlite(report_id, kpis);   // the existing db.transaction(...) wrapper, renamed
}
```

Same exported name/signature. The sqlite `db.transaction` wrapper is preserved verbatim inside
the sqlite helper (so the default path keeps its atomicity + synchronous return); the pg helper
uses `await H.runTransaction(async () => {…})`.

## Dialect rewrites (recipe)

- `datetime('now')` → `now()` (TIMESTAMPTZ columns)
- `.lastInsertRowid` → `.lastID` (ensureReport/ensureWeek/etc. that return the new row)
- `db.transaction(() => {…})()` → `await H.runTransaction(async () => {…})`
- `INSERT OR IGNORE` → `INSERT … ON CONFLICT DO NOTHING`; `INSERT … ON CONFLICT(report_id) DO UPDATE`
  in `saveHelpdeskData` is already pg-valid (keep, swap `datetime('now')`→`now()` + `excluded`→`EXCLUDED`)
- `substr(start_date,1,7)` stays (TEXT month-prefix match)
- COUNT/SUM scalars → JS numbers via the adapter's type-parsers
- `getReport`/`getMonthlyEdits` JSON.parse of helpdesk/monthly sub-fields is pure JS — reused as-is

## Sync-dispatch invariant (default path safety)

Every forked function returns **synchronously on the sqlite backend** (returns the value, not a
Promise); only the pg branch returns a Promise. This keeps the not-yet-awaited server.js callers
working on the default backend even before the route-wiring pass. Verified the same way as 4B
(a sqlite smoke asserting `getReport(...) instanceof Promise === false`).

## Known deferred interaction

`getMonthlyData` (4D assembler) and `getWeekSummaryData` (4C) both call `getReport`.
- `getWeekSummaryData` is forked here and awaits `getReport` in its pg branch.
- `getMonthlyData` stays sqlite (4D). Once `getReport` is async-in-pg, `getMonthlyData` can't run
  under pg until 4D forks it to `await getReport` — but it already reads `request_records` (absent
  until 4D), so it is non-functional in pg regardless. No 4C action; 4D will await `getReport`.

## Copy script

`tools/pg/copy-reports-reports.js` — one-shot idempotent sqlite→pg copy of the 10 tables in FK
order: `weeks` → `weekly_reports` → {`infra_kpis`, `helpdesk_data`, `lights`, `action_items`} →
`monthly_reports`, `annual_objectives`, `site_module_codes`, `infra_kpi_catalog`. (`sites`
already handled by `copy-reports-auth`.) **Column lists must include the ALTER-added columns**
(`weekly_reports.created_by`, `action_items.department`/`comment`). Upsert on PK; advance each
IDENTITY sequence via
`GREATEST((SELECT COALESCE(MAX(id),0) FROM t), 1)`. Skips cleanly when PG is unreachable. Same
structure as `copy-reports-auth.js` / `copy-reports-config.js`.

## Testing (TDD)

`tests/pg-reports-reports.test.js` — pg backend against a throwaway DB via `tests/pg-helpers.js`;
skips cleanly when PG down. Header sets `REPORTS_BACKEND=postgres` + `SDP_DATA_DIR` + dummy
`DASH_USER`/`DASH_PASS` (same as `pg-reports-auth.test.js`). A site is created via the forked
`createSite` (4B) so reports have a valid `site_id`. Increments:

1. **schema + catalogs** — `003_reports.sql` idempotent re-apply; catalog tables present + empty-seed no-op.
2. **weeks + report header** — `ensureWeek` dedup (UNIQUE year,week), `ensureReport` create+idempotent (UNIQUE site,week), `getReport` shape, `listReports` filters, `updateReportStatus` (draft→submitted→draft, stamps submitted_at/by), `touchReport` (bumps updated_at).
3. **per-report data** — `saveInfraKpis` replace, `saveHelpdeskData` upsert (insert then update same report_id) with JSON round-trip, `saveLights`/`saveActionItems` (incl. `department`/`comment`) + `getLightsForReport`/`getActionsForReport`, `listAllWeeksWith*`, `getPreviousWeekOpenActions`/`getPreviousWeekInfraKpis`.
4. **delete cascade** — `deleteReport` wipes infra_kpis/helpdesk_data/lights/action_items (FK CASCADE).
5. **monthly + objectives** — `getMonthlyReport`/`getMonthlyEdits`/`saveMonthlyEdits` (UNIQUE site,year,month upsert), `getAnnualObjectives`/`saveAnnualObjectives`.
6. **getWeekSummaryData** — aggregates submitted reports for a week (awaits getReport).
7. **copy parity** — seed a sqlite fixture (week+report+kpi+light+action+monthly+objective), run `copyReportsReports`, assert parity + sequence advance.

sqlite path regression: existing sqlite report behaviour stays green (no-op dispatch); add a
sqlite synchronous-return smoke for `getReport`/`saveInfraKpis`.
