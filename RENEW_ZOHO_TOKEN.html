🔑 Zoho Token Renewal Guide

Endeavour Mining IT Dashboard · Use this guide whenever the data sync stops working with a "Token failed" error

When do you need this?

The dashboard syncs live ticket data from ManageEngine Analytics Plus using a Zoho OAuth token. The refresh token can occasionally become invalid if the Zoho account password is changed or the app is revoked in the API console. When this happens, PM2 logs will show:

✗ Token failed: Request failed with status code 400

The dashboard keeps serving from cache, but live data stops updating. Follow the steps below to fix it in ~5 minutes.

1

Confirm the token is actually broken

On the server, check the PM2 logs:

C:\Apps\SDP-Dashboard> pm2 logs endeavour-dashboard --lines 20

Look for the red error line. If you see ✅ Token Refreshed instead, the token is working fine and you don't need this guide.

2

Log in to the Zoho API Console

  1. Open a browser and go to https://api-console.zoho.com
  2. Zoho will ask you to Verify your identity — click Send OTP
  3. Enter the OTP from your Endeavour email inbox
  4. You will land on the API Console main page
💡 You must use the same Zoho account that was used to originally set up the dashboard credentials.
3

Generate a new authorization code Time-sensitive

  1. Click Self Client in the left sidebar
  2. Click Generate Code
  3. In the Scope field, paste exactly:
MEAplus.fullaccess.all
  1. Set Time Duration to 10 minutes
  2. Click Create
  3. Zoho shows a one-time authorization code — copy it immediately
⚠️ The authorization code expires in 10 minutes. Complete Step 5 before it expires.
⚠️ Do NOT use the narrower read-only scope (MEAplus.data.read,MEAplus.metadata.read). It looks like the right "least privilege" choice but triggers errorCode 7301 SECURITY_NOT_PERMITTED on several views (Survey Results, REQUEST_TABLE, MAJOR_INCIDENTS) with a misleading "user does not have permission" message. Confirmed 2026-05-27 in prod.
⚠️ Do not use ZohoAnalytics.* scopes (e.g. ZohoAnalytics.fullaccess, ZohoAnalytics.data.read) — those are for Zoho Analytics, not ManageEngine Analytics Plus, and will cause INVALID_OAUTHSCOPE error (errorCode 8540).
ScopeWhat it allowsStatus
MEAplus.fullaccess.allFull access to all Analytics Plus APIs✅ Use this
MEAplus.data.read,MEAplus.metadata.readRead-only data + metadata (looks right, but doesn't work)❌ Triggers 7301 on several views
4

Make sure get-token.js is on the server

The get-token.js script handles the token exchange automatically. If it's not already in C:\Apps\SDP-Dashboard\, copy it from the source folder:

:: Copy the script to the server folder
C:\> copy "C:\Users\Admin\Documents\SDP-Dashboard\get-token.js" "C:\Apps\SDP-Dashboard\get-token.js"
💡 Keep get-token.js in your Documents\SDP-Dashboard folder permanently so you can always copy it over when needed.
5

Run the token exchange Time-sensitive

Open CMD as Administrator, then run — replacing <YOUR-CODE> with the authorization code from Step 3:

C:\Apps\SDP-Dashboard> node get-token.js <YOUR-CODE>

Example:

C:\Apps\SDP-Dashboard> node get-token.js 1000.abc123def456.xyz789

If successful, you will see:

✅ Got refresh token!

.env updated with new ZOHO_REFRESH_TOKEN.
Now run: pm2 restart endeavour-dashboard --update-env

Done — delete this file afterwards: del get-token.js
⚠️ If you see Exchange failed, the code has expired. Go back to Step 3 and generate a new one.
6

Restart the dashboard with the new token

The --update-env flag is required — without it PM2 uses the old cached environment and ignores the new token:

C:\Apps\SDP-Dashboard> pm2 restart endeavour-dashboard --update-env
✅ You should see PM2 restart cleanly with status online.
7

Verify the token is working

Check the PM2 logs for the confirmation message:

C:\Apps\SDP-Dashboard> pm2 logs endeavour-dashboard --lines 15

Look for:

[Token] ✅ Refreshed #1, expires 10:29:38 AM | granted scope: MEAplus.data.read,MEAplus.metadata.read

This confirms the new token is active and the correct scope was granted. The dashboard will now sync live data again automatically every 2 hours.

💡 You can also open the dashboard at http://<server-ip>:3456 and click ⚡ Force Sync on the main dashboard to immediately pull fresh data.
8

Clean up

Delete the exchange script from the server folder for security:

C:\Apps\SDP-Dashboard> del get-token.js
💡 Keep a copy in C:\Users\Admin\Documents\SDP-Dashboard\get-token.js for next time.
✓
